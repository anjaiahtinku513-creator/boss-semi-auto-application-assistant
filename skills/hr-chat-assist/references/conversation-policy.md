# 对话策略与升级规则

## 意图分类

每条消息可以有一个主要意图和多个次要意图：

| 意图 | 常见内容 | 默认处理 |
|---|---|---|
| `basic_screening` | 年限、学历、技能、行业经验 | 用已验证事实直接回答，缺口不掩饰 |
| `role_interest` | 是否考虑、为什么投递 | 结合岗位核心职责给简短动机 |
| `salary` | 期望薪资、当前薪资、是否可谈 | 仅使用用户确认的口径和区间 |
| `availability` | 在职状态、到岗时间、面试时间 | 不替用户承诺，给可编辑草稿 |
| `location` | 通勤、出差、搬迁、办公方式 | 陈述已确认边界，不自动让步 |
| `departure_reason` | 离职原因、空窗期 | 真实、简短、面向下一步，不攻击前雇主 |
| `portfolio_or_test` | 作品集、笔试、作业 | 核实范围、截止时间、数据与版权风险 |
| `interview_invite` | 时间、地点、会议链接、轮次 | 高意向，人工确认并触发面试准备 |
| `offer_or_negotiation` | Offer、定薪、签约、背调 | 人工接管，不自动承诺 |
| `rejection_or_hold` | 暂不合适、流程暂停 | 礼貌收尾，可询问一项可执行反馈 |
| `suspicious` | 收费、押金、验证码、代收款、异常链接 | 停止常规流程并提示风险 |
| `unclear` | 语义不完整或缺少上下文 | 提出一个最小澄清问题 |

## 风险等级

- `low`：一般岗位信息、技能确认、补充材料说明。
- `medium`：薪资、离职原因、到岗时间、地点、加班、出差、作品测试。
- `high`：面试时间确认、联系方式交换、Offer、定薪、背调、证件、签约和任何外部承诺。
- `critical`：付费、贷款、验证码、银行卡、代收转账、可疑软件或远程控制要求。

`high` 和 `critical` 必须明确写“人工接管”；仍可为 `high` 提供草稿，但不得暗示系统可以代发。`critical` 优先给风险处理建议，不生成迎合对方的回复。

## 敏感问题处理

### 期望薪资

- 先确认币种、税前或税后、月薪或年薪、月数、奖金和提成口径。
- 用户给出区间时，可以说明区间及影响因素；不要自行下调底线。
- 用户未确认时使用 `[请填写期望区间]`，不从过往薪资推算。

### 当前薪资

- 不虚报。若用户不希望披露，可礼貌把讨论转向岗位预算和期望区间。
- 不声称用户有法律义务披露或拒绝披露；只提供沟通选项。

### 离职原因与空窗期

- 只用用户确认的真实原因。
- 保持中性，不编造“组织调整”“家庭原因”或“职业规划”。
- 可以把重心放在下一岗位的真实诉求，但不能替换事实。

### 到岗、加班、出差与搬迁

- 给出明确边界和可商量部分。
- 不使用“都可以”“随时到岗”等绝对承诺，除非用户明确确认。

### 婚育、健康及家庭情况

- 提醒这是个人敏感信息，并提供简短边界型回答。
- 不代用户披露，不编造，也不进行法律定性；如需法律建议应查阅适用地区的最新权威信息。

## 去重与状态

标准状态：

```text
received -> drafted -> awaiting_user_selection -> user_selected -> user_sent -> waiting_hr
```

- Skill 只能自动推进到 `awaiting_user_selection`。
- 用户选择文本但未说明发送时，只到 `user_selected`。
- 只有用户明确报告“我已经发送”时才能到 `user_sent`。
- 同一规范化消息内容已经有 `drafted` 或之后状态时，不因重复采集重新建议发送。用户主动要求改稿或更多选项时可以继续起草，但不把新草稿记为已发送，也不覆盖原发送记录。
